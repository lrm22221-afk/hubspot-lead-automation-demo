# Importing the n8n workflow

`hubspot_lead_workflow.json` runs the same flow as the TypeScript service:
webhook → validate/score/route (Code) → search contact → PATCH or POST contact → deal → task → Slack → respond.
Every HubSpot HTTP node retries (5 tries, 2 s apart) and sends failures to **Dead-letter + error alert**.

The Code nodes contain a bundled copy of `src/core.ts` and `rules/rules.json`, generated by `npm run build:nocode`.
Don't edit them in n8n if you want to keep them in sync; edit the sources and rebuild.

**Tested:** CI runs the Code nodes from this JSON, chained against the mock HubSpot API (`tests/nocode.test.ts`).
**Not tested:** importing and running it on a live n8n instance or a real HubSpot account.

## Steps

1. n8n → Workflows → **Import from File** → `n8n/hubspot_lead_workflow.json`.
2. Set environment variables on the n8n instance and restart it:
   `WEBHOOK_TOKEN`, `HUBSPOT_PRIVATE_APP_TOKEN`, `SLACK_WEBHOOK_URL`, optionally `HUBSPOT_BASE_URL`, `HUBSPOT_SCORE_PROPERTY`,
   `DEFAULT_CALLING_CODE`. If `$env` access is blocked on your instance, replace the expressions with n8n Credentials
   (Header Auth for HubSpot).
3. Edit owner ids in `rules/rules.json` and rebuild (or edit the **Validate, score & route** node directly).
4. Activate, then point your form at `https://<n8n>/webhook/lead` with header `X-Webhook-Token: <WEBHOOK_TOKEN>`
   (or `?token=` for tools that cannot set headers).
   For Jotform: Settings → Integrations → WebHooks. Jotform posts multipart form data with a `rawRequest` field;
   confirm in the first execution that the Webhook node's `body` contains `rawRequest` (the Code node reads it).

## Differences from the TypeScript service

- n8n's built-in retry waits a fixed time between tries; it does not read `Retry-After` or back off exponentially.
- Dedupe of submission ids, the round-robin counter and the dead-letter list live in workflow static data, which n8n
  persists only for production (active) executions. Use a database for anything serious.
- There is no replay endpoint; re-run failed executions from n8n's execution list or re-post the stored payload.
